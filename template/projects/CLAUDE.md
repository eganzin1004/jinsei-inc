# プロジェクト台帳 — Projects

## 役割

すべての「取り組み」を管理する台帳です。
部署は永続的な機能ですが、プロジェクトは時限的な取り組み。ここで一覧・進捗・関係部署を管理します。

## プロジェクトとは

- 複数の部署をまたいで動く取り組み
- 始まりと終わり（またはマイルストーン）がある
- 例: プロダクト開発、資格の取得、引っ越し、健康の改善、外部発信

## ファイル管理

- 1プロジェクト1ファイル: `project-name.md`
- ステータス: `active` / `on-hold` / `completed` / `abandoned`
- テンプレートは `_template.md` を使う

## ルール

- プロジェクト固有のコンテキスト（背景・目的・意思決定）はここに書く
- 技術的な実装詳細は `engineering/`、調査結果は `research/`、デザインは `creative/` へ
- 完了したら `completed` にして残す（削除しない）
- 秘書役が進捗を確認するときはこのフォルダを見る

## 振り分けの判断

| どこに書くか | 内容 |
|---|---|
| `projects/` | プロジェクトの概要・ステータス・方針・横断的な意思決定 |
| `engineering/docs/` | 技術設計・アーキテクチャ |
| `research/projects/[project-name]/` | 市場調査・競合分析の結果（プロジェクト別） |
| `creative/assets/` | デザインブリーフ・素材方針 |
| `ventures/monetization/` | マネタイズ戦略 |
| `secretary/notes/decisions.md` | 日々の小さな意思決定 |

### 次のマイルストーン欄

- 全台帳の概要に `- **次のマイルストーン**: YYYY-MM-DD | 内容` を1行置く
- active なら必ず日付つき。未定なら `未設定`（起動時チェックが警告を出す）。on-hold / completed は `なし`
- 台帳を更新したら、このマイルストーンも見直す
- 起動時チェックがこの行を読んで浮上させます

### 成果物は台帳に載っているかで判定する

台帳を更新したかではなく、**作ったものが台帳の関連ファイル欄に載っているか**で判定します。別の節を更新していても、成果物が載っていなければ終わっていません。

**古い台帳から再開すると、すでに作ったものを作り直します。** ここが引き継ぎそのもので、他のすべてが「台帳は本当のことを書いている」前提で動いています。
