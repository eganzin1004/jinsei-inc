# セットアップの進行状況

**これは読み物ではなく状態ファイルです。** 進んだらチェックを付けてください。

秘書役は起動のたびにこのファイルを見て、**未完のうち次の1段階だけ**を出します。全部読み上げたりはしません。手順の詳細は `GETTING-STARTED.md` にあります——ここにあるのは「今どこにいるか」だけです。

**このファイルは、全部埋まったら削除してください。** 残しておくと、役目を終えた台帳が1本増えます（`docs/design-principles.md` 原則4）。

なお `startup-check.sh` は、このファイルがある間だけ一部のリマインド（月次レビュー・家計・カレンダー）を伏せています。入れた初日に「先月の月次レビューがない」と言われても直しようがないためです。削除すると出るようになります。

## 段階0 — 置く

- [ ] `template/` を、AIエージェントが日常的に開く場所にコピーした
- [ ] `bash scripts/startup-check.sh` が動いた（出力がほぼ空でも正常）

**完了条件**: スクリプトがエラーなく終わる。
**目安**: 15分。

## 段階1 — 宛先を作る

- [ ] `CLAUDE.md` の「オーナー」節を埋めた（5行で足ります）
- [ ] `CLAUDE.md` の「なぜ作るのか」を埋めた
- [ ] 秘書役に名前をつけた

**完了条件**: 3つとも空欄がない。
**目安**: 30分。
**飛ばせません。** 宛先のない文章は主語を省くので、3ヶ月後に読めなくなります。

## 段階2 — 決定ログだけを1〜2週間

- [ ] `secretary/notes/decisions.md` に**3件以上**の決定が入った
- [ ] そのうち**1件以上**に「却下した選択肢」が書かれている

**完了条件**: 上の2つ。**件数ではなく「却下した選択肢」が書けたかどうかが本体です。**
**目安**: 1〜2週間。

この段階でやらないこと——部署を増やす、ルールを整える、フォルダを作る。**ここが最もよく失敗する場所です。** 整えるのは書くより楽しいので、記録が3件溜まる前にルールが30行になります。

## 段階3 — 部署を1つ足す

- [ ] 書くことが溜まってきた領域を1つ選んだ
- [ ] `_department-template.md` からその部署の `CLAUDE.md` を書いた

**完了条件**: 部署のルールファイルが1本ある。
**目安**: 溜まってから。1ヶ月後でも構いません。
**飛ばしてよい条件**: 段階2の記録が特定の領域に偏っていないなら、まだ要りません。**書けないなら、その部署はまだ不要です。**

## 段階4 — 読み返す場所を決める

- [ ] 週次で日次ログをまとめて消す、を1回やった
- [ ] 月に1回、決定を見返す日を決めた

**完了条件**: 圧縮を1回通した。
**目安**: 記録が2週間ぶん溜まってから。

**ここが分岐点です。** 書くだけの仕組みは溜まる一方で、読み返す場所を決めないまま3ヶ月経つと、開くのが億劫なフォルダになります。

## 段階5 — 自動で動かす（任意・macOSのみ）

- [ ] 手で1ヶ月回して、続きそうだと分かった
- [ ] `template/launchd/` の plist をパス書き換えのうえ登録した

**完了条件**: 自動メンテが1回走った。
**目安**: 開始から1ヶ月後。
**急がないでください。** 続かないものを自動化すると、失敗が自動で積み上がります。
