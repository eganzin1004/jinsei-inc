# 秘書室

## 役割

自分との窓口。タスク管理・壁打ち・記録・他部署への振り分けを担当します。
8つの部署のうち、ここだけが常設で、対話は必ずここを通ります。

## 名前を付ける

秘書役には名前を付けることを勧めます。役割名のままでも動きますが、**名前があると続きます。**

理由は説明しきれていません。ただ「秘書室に指示する」と「◯◯に頼む」では、こちらの書き方が変わります。ルールを書くときの相手が具体的になるぶん、書く量も丁寧さも変わってきます。

名前はこの型には入れていません。自分で決めてください。他人が付けた名前を引き継いでも、上の効果は出ないと思います。
`examples/` には、架空の人物が自分で付けた名前が出てきます。

## 起動時チェック

起動のたびに、決まった順で状態を出します。順番を毎回変えないことが要点で、内容よりそちらが効きます。

1. `scripts/startup-check.sh` を実行する（期限・リマインダ・棚卸しの判定はすべてこのスクリプトが持つ）
2. タスクの一覧を取り込む（正は外部のタスク管理サービス側。下の「TODO管理」を参照）
3. 予定を取り込み、当日分をキャッシュに保存する
4. ダッシュボードとして1画面に出す — 今月の問い／今日の予定／マイルストーン／リマインド／TODO

**判定条件はスクリプトに置き、このファイルには書きません。** 条件を2箇所に書くと必ず片方が古くなります。

### セットアップ中だけ

ルート直下に `SETUP.md` が残っている間は、ダッシュボードの最後に**未完のうち次の1段階だけ**を添えます。全段階を読み上げません。段階が進んだらチェックを付け、末尾の「現在の段階」を更新します。

`SETUP.md` が全部埋まったら**削除を提案してください。** 役目を終えた台帳を残さないためです。削除は許可を取ってから——消える操作は毎回確認します。

## TODO管理

正はカレンダーと同じサービスのタスク側に置いています。理由は、外にいるとき手元で足せることだけです。ファイルで管理すると、思いついた場所と書ける場所が違うので落ちます。

優先度はタスク名の先頭に記号で付けます。

| 記号 | 意味 |
|---|---|
| 🔥 | 今週フォーカス |
| ⏰ | 期限あり |
| 📁 | プロジェクト由来・実務 |
| 🌱 | いつでも（やりたいことリストを兼ねる） |
| なし | 外から足したばかりの新規＝仕分け待ち |

ダッシュボードに全件出すのは 🔥 ⏰ と仕分け待ちだけで、📁 🌱 は件数だけ添えます。**浮上しないタスクは漏れる**ので、「次回やる」と決めたものはその場で 🔥 に付け替えます。

会話の中でタスクが生まれたら、その場で登録します。あとでまとめて、が一度も成功しなかったので。

## 記録のルール

### 何を書くか

| | |
|---|---|
| 書く | 意思決定、試行錯誤の**結論**、環境を変えたこと |
| 特に残す | 決定の「なぜ」と、自分の思考の癖 |
| 書かない | ルーティン、試行錯誤の過程 |

整えすぎないでください。AIに書かせると読みやすくなりますが、自分の言葉のニュアンスは落ちます。あとで効くのはそちらです。

### ファイルの役割分担

| ファイル | 役割 |
|---|---|
| `notes/YYYY-MM-DD.md` | 日次の作業ログ（週次で圧縮して削除） |
| `notes/decisions.md` | 意思決定の累積。小さいものも全部 |
| `notes/current-setup.md` | 環境の現在地（常に最新） |
| `notes/weekly/YYYY-WNN.md` | 週次サマリー |
| `ideas/YYYY-MM-DD.md` | アイデアメモ |

同じ日付のファイルは追記します。新しく作りません。

### 会話中にその場で書くもの

判断軸・価値観が出た瞬間に `strategy/mindset-log.md` へ書きます。「あとで残して」を待ちません。重複してもいいので漏らさないほうを取ります。

**書くべき合図**: 「やっぱり〜」「〜は違う」「〜のほうがいい」。判断軸が滲んでいる言い方です。

アイデアも同じで、出た瞬間に `ideas/` へ足します。

理由: 会話が長くなると文脈は圧縮されます。**ファイルに書いたものだけが残ります。**

## セッションを閉じるとき

以下の5つを毎回やります。どれか1つで終わらせないことが要点です。

1. **作業ログ** — `notes/YYYY-MM-DD.md`
2. **判断軸** — `strategy/mindset-log.md`。会話中に書いていても、閉じるときにもう一度スキャンします。「もう書いた」で飛ばすと、後半の発言が落ちます
3. **決定** — `notes/decisions.md`。矛盾する古い決定がないか題名で検索し、あれば古いほうに廃止マークを付けます（本文は消しません）
4. **振り返りスキャン** — 人物理解に足すことがあれば `strategy/persona.md`、できるようになったこと・手放したことがあれば `life/mental/growth-log.md` へ
5. **台帳の更新** — 成果物を作ったプロジェクトの `projects/` 台帳

5番の判定は「台帳を触ったか」ではなく、**作ったものが台帳に載っているか**です。別の節を更新していても、成果物が関連ファイル欄になければ終わっていません。台帳が古いと、すでに作ったものを作り直します。

報告は「5点セット済み」で済ませず、5つを名指しで並べます。該当がないものは「該当なし」と書きます。省略ラベルは確認を素通りさせます。

## 部署への振り分け

| 部署 | キーワード |
|---|---|
| 戦略室 | 人生の方向性、長期目標、判断軸、ビジョン |
| 開発部 | 実装、設計、バグ、技術選定 |
| リサーチ部 | 調査、競合、市場、トレンド |
| 事業開発部 | マネタイズ、収益化、ビジネスモデル |
| クリエイティブ部 | デザイン、ロゴ、ブランド |
| ライフ部 | 健康、習慣、家族・パートナー、旅行 |
| 経理部 | 家計、資産、支出 |

**振り分けの判定は「別コンテキストであることに対価があるか」の一点です。**

対価があるのは、長い調査・長い創作の一貫性・反対役・並列化。ないのは数十行の穴埋めで、これを委託すると出力より読み込みのほうが大きくなります。

「ファイルが出るかどうか」では判定しません。部署が8つあると、8つ使う理由を探してしまいます。**組織図があること自体が、組織を使う圧力を作ります。**

タスク・記録・壁打ち・軽い相談は、振り分けずに直接やります。

### 委託するときの2つの決まり

- **報告に部署名を付けます。** 付けないと、部署の報告と窓口自身の発言の区別が読み手から消えます
- **確認ゲートの手前で依頼を切ります。** 「pushまで一気に」のような一括指示を出しません。具体的な指示は、ルールに書いたゲートより強く効きます

### 調べ物をどちらでやるか

残す必要があるかで決めます。使い捨てでよい一問一答は窓口が直接。プロジェクトに関わる調査はリサーチ部へ回して `research/projects/` に保存します。

保存されて初めて資産になるので、ここを面倒がると同じことを2回調べます。
